# Prompt v3 — Diction Calibration

**Status**: Applied to `prompt-v3`
**Date**: 2026-05-21
**Relates to**: `prompt-direction-delta-conversational-sutra.md`
**Touches**: `lambda/commands.mjs`（starters）、`lambda/prompt.mjs`（demos + 一條規則）、`lambda/index.mjs`（welcome message）

## 問題

v3（Delta）把 v2 的 image-first 拿掉了，但只拿掉「結構層」的秀——長比喻、散文、image 優先級。**詞彙層的秀沒拿掉。**

一個平常的抽象意思，仍被換成壓縮過的具象意象：心裡放不下→「最佔位置」、煩惱的環節→「哪一段」、累→「耗電」、想一想→「拆開」。長比喻被砍成短比喻，比喻的習慣本身沒砍。delta 文件甚至把「丟一句最佔位置的話」當成正面範例——它比 v2 不秀，但還不是白話。

加上 v3 把「短／口語」操作成「字數少」。但真正的台灣口語是**鬆**的；砍掉連接、軟化的贅字，得到的是書面電報體，不是口語。

這些怪字散在 starter、few-shot demo、welcome message、跟 system prompt 裡會被逐字抄的句子。

## 4 條用字原則

1. **抽象的事用抽象的講法。** 心裡放不下的→「最在意／最放不下」，不是「最佔位置」；煩惱的環節→「哪件事／卡在哪」，不是「哪一段」。比喻留給真的能讓人看更清楚的時候，不是每個平常詞都換一個具象意象。
2. **口語是鬆的，不是短的。**「的話／先…一下／要是／都可以」這些連接、軟化的字不要為了省字砍掉。寧可多兩字像人講話。
3. **量詞、受詞講完整。**「金剛經裡的一句話」不是「一句金剛經」；「不用先想好怎麼說」不是「不用整理」。
4. **口語的受詞也要口語。** 別保留書面／學科名詞（句子、開口）再套個口語動詞（弄漂亮）充數——那只是把書面語包一層糖。

## 操作守則

**改 voice 就改 demo。** few-shot demo 的影響力遠大於 prose 規則——prompt 正文寫「人話優先」沒用，模型看到示範裡是「丟／佔位置／哪一段／拆」就照抄。語言基準、紅旗 list 是次要訊號。下次要動 voice，先動 `FEW_SHOT_DEMOS`，不要只在正文加規則。
