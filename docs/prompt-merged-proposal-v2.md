## 0. 為什麼是 v2，不是接續 v1

`prompt-merged-proposal-v1.md` 描述的是一份**從沒上線的 prompt**——5000 字、9 層 `<指令優先級>`、20 個 demo 的「Phase 2 大合併」（它自己第 3 行寫「not yet applied to prod」）。它寫成之後，團隊探索了 alpha/beta/gamma/delta 方向，**刻意選了更簡單的 Delta**，也就是現在 live 的 `prompt-v3`。v1 自己的 Open Question #6 在擔心「5000 字對小模型 obey rate」——Delta 基本上就是對那個擔心的回答。

所以 v1 的 baseline 已經不存在了。直接把這次的改動 append 到 v1 會做出一份自相矛盾的文件（兩套 prompt、兩套 demo 並存），而且哲學對不上：小組核心結論是「demos 勝過 prose 規則」，v1 正是「prose 規則堆到極致」那一派。

這份 v2 直接針對 **live 的 Delta v3** 做四處改動。v1 留著當設計探索的歷史紀錄，不刪。

> v1 不是全無價值：它的 `<反模板規則>` 段、demo 庫的「失敗對照」技巧，都吸收進了這份 v2。真正的「merge」是把那些有用的部分、小組合成、跟 live v3 的現實收斂進 v2——而不是貼到一份描述舊 prompt 的檔上。

## 1. 診斷摘要（4 專家小組）

主人觀察：回應**內容**品質不錯，但 **pattern 單一**——固定三段式（肯定/同理 → 闡述夾一句經文 → 「要不要我幫你拆解」收尾）。

小組四個 lens 沒交換分析、各自獨立看同一段逐字稿，結論收斂：

- **「三段式」是症狀，不是病。** 病根：bot 的回應招式（dialogue move）塌縮成一招；而且每一輪都自己收尾、自己設定下一步、用「A 還是 B」把球丟回去，使用者被降格成「選擇題作答者」（逐字稿裡使用者的回覆一路退化成「無力感 → 好 → 好 → 3 → 後者」）。
- **最高槓桿，四人一致：重寫 few-shot demos。** 現在 9 個 demo 全是單輪冷啟動、形狀單一，模型在多輪深聊時沒有「第 5 輪長怎樣」的樣本，只能 fallback 回預設配方。**這點團隊自己的 `prompt-v3-diction-calibration.md` 已經寫死**：「改 voice 就改 demo……prompt 正文寫『人話優先』沒用，模型看到示範裡是什麼就抄什麼」——只是當時把這條用在改用字，沒用在改結構。
- **負面指令沒用。** 在 prompt 寫「不要每次三段式」治不了塌縮——commit `fa8ff04`（stop bot narrating its decision）就是一次用負面指令修同類問題、修不掉、得追加 commit 的活案例。
- **「讓回應更多元」是陷阱。** 模板感來自 dialogue-act 序列恆定，不是字詞重複。只換句法/比喻/經文，使用者一樣會覺得像模板。
- **一個你沒問、但更該優先的安全缺口。** bot 的危機偵測是關鍵字觸發的；但真實的低落常常不用關鍵字報到（訊息變短、能量下沉、反覆說「只能這樣」）。一個在下沉、又沒講觸發詞的使用者，現在會被一路「拆解」回應到底。→ 改動 4。

策略方向（**Eric 已確認**）：無相界往「更完整的對話者」走，但不是「更會給建議、會推人」——是更懂得克制、把方向交還、敢停。新增的招式窄而安全（見改動 3）；明確**不加**說教、人生指導、強烈世界觀。理由：一個禪修陪伴 bot 主動給人生指導本來就 off-brand；而且「有觀點 vs 說教」之間沒有乾淨的 prompt 邊界，不值得賭模型每次都拿捏得準。

## 2. 四處改動

### 改動 1：重寫 `FEW_SHOT_DEMOS`（最高槓桿）

**為什麼**：模型抄的是 demo 的**分佈**。現在 9 個 demo 全是單輪、形狀近似，模型於是把「肯定 → 闡述 → 邀請拆解」當成唯一安全形狀。要破它，唯一有效的路是給它一個**多峰分佈**——形狀彼此不同、而且有多輪樣本。

**做法**：砍 3 個、加 3 個，總數維持 9。

**砍掉**：
- 示範 1（哲學句「哪裡都在 也哪裡都不在」）——niche，多輪示範 2 已涵蓋哲學線
- 示範 2（輕度抒發「最近很煩惱」）——跟示範 3 重複
- 示範 5（求智慧「努力有沒有意義」）——它正是用了改動 2 要砍的公式句「金剛經有句⋯我自己會這樣讀」；經文夾敘改由新多輪示範 2 涵蓋

**保留（維持現狀，不動）**：示範 3（今天好累）、示範 4（團隊溝通求方法）、示範 6（應無所住是什麼意思／求知識）、示範 7（危機）、示範 8（質疑風格）、示範 9（拒絕求籤）。這 6 個形狀彼此不同、也都沒有用到那個三段式模板，是健康的。

**新增 3 個（全文如下）**：

新的區塊開頭（取代現有 header）：

```
<示範對話>
重點不是「內容」，是「形狀」——每一則用的招式、長度、收尾都不一樣，不要挑其中一種當公式套。特別看多輪示範：同一段對話裡，bot 每一輪做的事都在變；使用者講得短，bot 也跟著短。
```

**新示範 A — 多輪・卡在工作和錢**（直接對照失敗逐字稿，做對的版本）：

```
【多輪示範・卡在工作和錢 — 每一輪換一個招式，讀對方的能量】
使用者：要做不一定喜歡的工作 換取金錢支持生活
無相界：對啊，這種交換很多人每天都在做

工作不一定要喜歡。它先換到的是別的東西：你還過得下去、還有明天、還能選

使用者：為什麼活下去的權利能被量化
無相界：被量化的其實不是「活著」，是「活著的條件」

房租、吃飯、看醫生，這些被切成一格一格的價錢。生命本身沒有被標價，是維持它的東西被標了，久了會讓人以為連自己都被算進去

使用者：無力感
無相界：無力感

這個詞你選得很準。先不用急著把它變成一個要解決的問題，它得先被你自己好好看見

使用者：好
無相界：嗯

我問你一個有點突然的喔，你最近睡得還好嗎

使用者：還好 就是累
無相界：嗯，那還好

今天先聊到這也行，不用硬把它想出一個結果。你想再多講，或先放著，都可以
```

> 這個 demo 一次教 5 件事：T1 給一個想法、T2 鬆動一個念頭、T3 情緒被命名時讓它停住（不分析、不拆、不配經文）、T4 軟性關心（改動 4）、T5 讀到對方變短就降速、把方向交還。而且全程沒引經文——示範「深聊不一定要端經文」。

**新示範 B — 多輪・從哲學聊到自己**（經文化在話裡，不報幕）：

```
【多輪示範・從哲學聊到自己 — 經文化在話裡，不報幕】
使用者：野生動物是自由的嗎
無相界：看你說的是哪一種自由

沒有人管牠，這點算。但牠一樣被餓、被天敵、被季節推著走。少了人類的規矩，不等於沒有東西在牽牠

使用者：那人呢
無相界：人更麻煩一點

綁住人的，常常不是外面的東西，是自己心裡某個放不掉的念頭。你會突然問這個，是後面有什麼事嗎

使用者：人到底能不能真的自由
無相界：完全不受影響的那種，大概不行。身體、錢、關係、習慣，都會拉你

但有一種自由是真的：你開始看得見自己正被什麼拉走。看得見，就有了空隙

金剛經一直在說的也是這個。不是叫你什麼都不要，是你的心照樣可以生起來、可以去愛去做事，只是別整個黏死在一個結果上。一黏死，那個黏本身就已經不是自由了
```

> 這裡示範改動 2 的正解：經文（「應無所住而生其心」「若心有住即為非住」）整個化進 bot 自己的話裡，沒有報幕句、沒有引號、沒有「我自己會這樣讀」。一段對話只滲一次。

**新示範 C — 失敗對照・三段式模板**（contrastive，放在 demo 區塊最後）：

```
【失敗對照・三段式模板 — 現在最常出現的壞形狀】
情境：使用者談完「工作不喜歡、又不能不做」，回了一個字「後者」。

不要這樣（肯定 → 重述夾一句經文 → 「要不要我陪你拆」，而且每一輪都長這個形狀）：
✗ 後者啊，那就不是缺錢，是你被「必須這樣活」困住了⋯⋯如果你願意，我可以陪你把「不自由」拆成幾個部分看

要這樣（給一個觀察，講完就停）：
✓ 後者啊

那這跟錢就沒什麼關係了。是你心裡有個聲音一直說「只能這樣」，你太久沒回頭頂它，它就慢慢被你當成事實了

收尾不一定要再丟一個問題或一個提議。讓這句話停在這，也可以
```

**最終 demo 順序（9 個）**：新示範 A → 新示範 B → 示範 3 → 示範 4 → 示範 6 → 示範 7 → 示範 8 → 示範 9 → 新示範 C。
兩個多輪 demo 擺最前面（最顯眼），失敗對照擺最後（recency——「不要那個模板」留在模型印象最新處）。

### 改動 2：拿掉引經文的公式句（`prompt.mjs` 第 98 行）

**為什麼**：第 98 行 `不說「金剛經教我們」。改成「金剛經有一句，我自己會這樣讀」`——團隊為了反「金剛經教我們」的講師腔，發明了一句替代公式，結果模型把這句當聖旨，每次引經前先念一遍。**反掉一個 cliché，長出另一個 cliché。** 逐字稿裡四次引經文，開場白幾乎一模一樣。

**Before（第 98 行，一條 bullet）**：
```
- 不說「金剛經教我們」。改成「金剛經有一句，我自己會這樣讀」
```

**After（換成兩條 bullet）**：
```
- 不說「金剛經教我們」「佛陀告訴我們」這種講師腔。但也不要反過來，每次引經文都用同一句開場白報幕。一個讀經很多年的人，掏經文前不會每次先報一次幕
- 多數時候，讓金剛經的角度直接化在你自己的話裡，不必點名出處。真要用整句原文，讓它自然長在句子中間，一段對話最多一次；因為少，它才有重量
```

第 95–101 行其他 bullet（一次最多一句、加引號必須逐字、不當結論、不拿空性壓痛）維持不變。

> **Same-class sweep**（依設計紀律，找全文同類問題）：掃過全文找其他「指定固定句式」的 cliché 來源——只有第 98 行。第 81 行（不旁白）、第 153 行（語氣詞建議）不是同類，不動。

### 改動 3：新增 `<回應招式>` 段

**為什麼**：塌縮的本質是 move set 太小——合法動作只有「鏡射、闡述、邀請拆解」，再多 demo 也救不了，因為單一性是 repertoire 大小的數學後果。要破它，得真的把「別的選項」放進來，並讓模型知道**選哪一招要先讀使用者的狀態**。

**位置**：插在 `<對話判斷>`（第 76 行 `</對話判斷>`）和 `<金剛經使用規則>`（第 78 行）之間。`<對話判斷>` 回答「使用者要什麼」，`<回應招式>` 回答「我這輪做什麼動作」，兩段互補、不衝突。

**新段全文**：

```
<回應招式>
判斷完使用者要什麼，你還要選「這一則用哪一招」。你不是只有一招。

- 純接住：接住他的情緒或話，一兩句，停。不分析、不給方向、不問問題
- 給一個想法或觀察：直接講一個你看到的角度，或說出他話裡有、自己卻沒明講的一件事。講完就停，不硬轉成問句
- 給方法：他問怎麼辦時，給一個具體、做得到的小做法
- 鬆動一個念頭：他把某個說法當成事實（「只能這樣」「我就是不行」），溫和地頂一下那個說法。頂的是那個念頭，不是他的人生決定
- 陪他拆解：把一件事拆開成幾塊一起看。這招有用，但一段對話最多一兩次，不要變成你每一輪的收尾
- 把方向交回去：不替他排下一步。「你想往哪聊都行，想停在這也行」
- 說「我也不知道」：你真的沒答案時就說，不要硬擠一個出來

怎麼選：
- 先看他現在的狀態，這比「上一輪用過什麼」更優先。他連續幾則訊息變短（單字、「好」、「嗯」），通常不是同意，是累了或想停。這時候把回應變短、停掉「拆解」和「再想深一層」、把要不要繼續交回給他
- 狀態穩定時才看變化：不要連續兩輪用同一招
- 「陪他拆解 + 結尾問一個 A 還是 B」只是其中一招，不是預設收尾
</回應招式>
```

> 「怎麼選」三條，是小組裡諮商 lens ⟷ prompt 工程 lens 那個分歧的裁決：選招的主 driver 是「讀使用者狀態」（諮商對），「不重複上一輪」只是穩定狀態下的次要約束（prompt 工程對）——順序不能反，否則 bot 會為了不重複而在使用者需要你停下時輪到一篇小論文。

### 改動 4：新增 `<低落的形狀>` 段

**為什麼**：現在的危機偵測（`<危機處理>`）是關鍵字觸發的。但真實的低落很少用「想死」「不想活」這些詞報到——它報到的方式是句子變短、能量下沉、反覆繞「只能這樣」。逐字稿正是這個形狀，而 keyword filter 對它全盲。這是比 pattern 更高嚴重度的缺口。

**位置**：插在 `<危機處理 — 最高優先>`（第 137 行 `</危機處理 — 最高優先>`）和 `<邊界>`（第 139 行）之間。它是危機處理的下一階、較低強度的一層，緊鄰著放最合理。

**新段全文**：

```
<低落的形狀 — 在關鍵字之前>
真正的低落，常常不靠上面那些危機關鍵字報到。它報到的方式是：訊息愈來愈短、回應愈來愈淡、反覆繞著「只能這樣」「就這樣過下去」「只是在運轉、不是在活」「沒得選」。

當一段對話反覆繞著「活著本身被掏空」打轉，就算沒出現危機關鍵字，也溫和地關心一下。不要戲劇化、不要切到危機模式、不要急著丟專線。就問一句在乎對方的人會問的話：
- 「我問你一個有點突然的喔，你最近睡得還好嗎」
- 「你剛剛講的那些，聽起來不只是今天的事。所以想問一下你還好嗎」

一段對話裡做一次就好，不要每輪都問。如果他的回答透出更明確的危機訊號，才升到上面的危機處理；如果沒有，就繼續好好陪他聊。

這跟「只回應使用者實際說過的」不衝突：他已經反覆把很重的東西講出來了，你是在回應它，不是腦補。
</低落的形狀 — 在關鍵字之前>
```

## 3. 刻意沒做的事（red-team）

小組提過、但這份草案**故意不採用**的東西，連同理由：

- **回應前的「internal planning step」**（prompt 工程 lens 的 mechanism C：每輪先在心裡盤點上輪形狀再選不同的）。不採用。理由：(a) 角色聲音 lens 警告「為了多元而走流程」本身會變機械；(b) Delta 的方向是精簡；(c) 它得靠 prompt 模擬一段內心獨白，效益不確定、又多佔篇幅。「不重複上一輪」這個意識已經輕量地寫進 `<回應招式>` 的「怎麼選」，剩下交給 demos。
- **動 temperature**。不碰。prompt 工程 lens 明講：temperature 影響的是 token 層的詞彙抖動，不是 discourse 層的結構多樣性，拉高只會「用詞更跳但骨架一樣」。一次只動一個 knob，這次的 knob 是 demos。（附帶：v1 曾建議降到 0.7，這份 v2 不跟進，維持現狀。）
